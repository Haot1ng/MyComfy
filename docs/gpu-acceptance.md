# 目标 GPU 机器的生成与交付验收

使用已经部署的用户 API、可受理的固定策略版本及专用生成账号。脚本会登录该账号，上传用例指定的素材，按用例发起真实生成并下载视频。单会话登录会替换该账号的旧会话。每轮结束会退出本次登录。

## 准备用例

在目标机记录引擎提交号、依赖节点版本和模型文件摘要。按实际部署填写以下 JSON，保存为 `case.json`。模板中的 `null` 需要换成目标机及工作流实际使用的整数。策略 Schema 决定 `inputs` 和 `uploads` 的字段名。记录的种子、尺寸、帧数和编码设置应与策略工作流的实际参数对应。

```json
{
  "environment": {
    "gpu_model": "<GPU 型号>",
    "vram_mib": null,
    "driver": "<驱动版本>",
    "comfyui_commit": "<引擎提交号>",
    "node_versions": {"<节点包>": "<提交号或版本>"},
    "model_sha256": {"<模型名>": "<64 位十六进制摘要>"},
    "disk_type": "<磁盘及涉及的卷>",
    "instance_count": null,
    "condition": "warm",
    "preparation": "<记录何时、用哪个工作流完成预热>"
  },
  "tasks": [{
    "strategy_version_id": "<已发布版本 ID>",
    "inputs": {"prompt": "<代表性提示词>", "seed": null},
    "uploads": {"reference_asset_id": "reference.png"},
    "input_dimensions": "<宽 × 高>",
    "frames": null,
    "encoding": "<编码器、容器和帧率>",
    "seed": null
  }],
  "repetitions": 1
}
```

素材路径相对于用例文件。多素材参数可写成路径数组。同一文件在一次测量中复用上传结果。已有输入素材 ID 可直接写在 `inputs`。同批混合工作流时在 `tasks` 中添加各项，逐项指定策略版本。多实例部署使用相同输入组合、种子与采样窗口复测。

## 运行与读数

从项目根目录运行。密码从终端交互读取，自动执行时可通过环境变量 `MYCOMFY_ACCEPT_PASSWORD` 提供。报告保存实际提交的参数和上传素材的映射，使用验收样本及受限目录。

```bash
uv run --locked python scripts/accept_gpu.py \
  --url https://video.example.org --username acceptance \
  --case case.json --output evidence/run.json --media-dir evidence/samples
```

脚本创建新的报告文件。每次提交之前先写入 `client_batch_key`，收到响应后保存批次和任务 ID。HTTP 超时或脚本中断后先用该键及请求审计核对原批次，仍在运行的任务继续由 Worker 处理。再次独立运行脚本会提交新一轮生成。

- 单项延迟从发起批次提交计时，直到用户 API 对该项每个完整视频都返回正确的单字节 Range。完整下载的字节数及 SHA‑256 与 Asset 登记一致，这个样本才会计入 P50、P95。报告采用最近秩并给出样本数。
- 批次耗时截止最后一个任务首次被观察为终态。吞吐以完整校验通过的任务数除以各批次观察时长之和。任务时间线记录轮询观察到的状态、执行 ID 与尝试序号。短于轮询间隔的阶段可能跳过。
- `delivery_verified` 表示本轮所有任务均成功且用户能读回匹配的字节。报告把部署人员提供的硬件及版本清单、API 读取的固定策略摘要、实际请求 ID 和仍待目标机取证的条目分别标明。
- 冷启动样本使用 `condition: cold`，每次只运行一轮。为覆盖进程启动和首次加载，在已配置实例暂停时发起受理，随后由目标机操作者启动该实例，并记录启动时间和代次。热态样本在同一环境完成预热后开始，按部署测量目标设置重复次数。

## 目标机补证

| 检查项 | 操作与记录 |
| --- | --- |
| 真实引擎关联 | 从任务进入执行详情，记录 `execution_id`、引擎实例及代次、客户端指定的 `prompt_id`、实际节点及种子，与同一代次的引擎队列、历史、输出位置和下载摘要对应。 |
| 丢失回执后的核对 | 在目标机专用验收实例上控制一次已接收请求的回执丢失。分别在生成中、生成完成后重启 Worker。记录恢复前后的任务与执行、引擎实际接收次数及最终产物摘要。两个场景各自需要看到接收次数为一。 |
| 定向取消 | 在运行中从正常用户接口取消专用测试任务，记录 API 返回的状态和引擎的实际反应。分别核对实际执行结束时间、槽位释放时间、受影响的执行 ID，以及固定策略对产物的可见性规则。 |
| 性能和容量 | 同步采集目标机 GPU 使用情况、工作卷和正式卷空间、引擎阶段和发布日志，注明采样间隔。按执行与代次记录排队、生成、后处理和发布用时，以及显存与磁盘峰值。将观测值与该部署设定的阈值逐项对照。 |
| 人工画质 | 使用保存的同种子样本核验画面、分段衔接、适用时的音画时长及播放器兼容性。记录评审人、样本摘要、日期及结论。 |

各项证据须来自对应部署及实际用例。尚无目标机记录的项目在验收报告中标为待验证。
